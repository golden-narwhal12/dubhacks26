# Architecture

One Electron/React/TypeScript application. Main owns files, encrypted credentials, provider network access, fixed toolchain execution and cancellation. A sandboxed preload exposes a narrow validated IPC contract. Browser mode supports manual editing and explicitly lacks desktop services. Domain logic has no UI/runtime dependencies.

## Project format

`.trace.json` is UTF-8 JSON with `schemaVersion: 2`, project identity/name/revision, component instances, explicit wire endpoints, independent wiring/schematic placement maps, firmware files and pin bindings. Parts reference immutable built-in package ID/version. Each terminal has a stable ID independent of its label and rendering position. Package data records exact manufacturer/identity/revision, source URL/location/revision/fact/units/status, firmware and simulation capabilities. Unsupported package versions are rejected, never remapped silently.

Nets are derived connected components over endpoints plus explicitly modeled internal equivalences. A resistor/LED does not short its two pins. Layout is not circuit meaning. Selection, tool activity, viewport and output are transient or workspace preferences, never the circuit. Diagnostics carry source revision, affected object IDs, rule, severity, evidence and next action. Recompute local checks without inference. Execution results retain revision provenance; semantic input keys determine freshness separately.

## Commands

`transact(project, {expectedRevision, summary, commands})` validates all inputs and the resulting project before returning a new revision. Commands add/configure/remove parts, connect/disconnect, move/rotate in a named view, replace a firmware file, and set/remove explicit pin bindings. Removal cascades connections, layouts and bindings. One failed command rejects the entire group. Expected revisions reject stale agent mutations. Snapshot history supports grouped undo/redo, each advancing revision to prevent ABA conflicts.

Shared interaction store selects stable component/terminal/wire/diagnostic IDs. Panels subscribe; no panel imperatively changes another. Explicit navigation can reveal code/evidence without selection stealing focus. Dockview owns pane arrangement; React Flow owns gesture rendering, never canonical topology. Monaco uses local bundled workers/assets, no CDN.

## Modules

- `src/domain`: schema, commands, topology, rules, history, example and typed tool contracts.
- `src/parts`: sourced immutable part packages; original vector illustrations with separate terminals.
- `src/ui`: dock shell, circuit, code, agent, inspector, output and tokens.
- `src/services`: participation controller, provider/tool contracts and execution model.
- `desktop`: Electron lifecycle/preload, credentials, provider adapters and toolchain.
- `tests`: topology/transaction/persistence/rules, provider fixtures, participation and desktop workflow.

## Boundaries

No arbitrary filesystem paths or shell tool. File dialogs mediate project access; sketches compile in a private temporary directory. Compiler and simulator children inherit a macOS `sandbox-exec` profile: network I/O denied; regular file contents restricted to system/SDK/tool roots, selected Arduino package/index data and build scratch; writes restricted to scratch/safe standard streams. HOME is preserved, build config/cache/download/user directories are redirected explicitly to scratch, and provider environment variables are omitted. No unrestricted fallback. User Arduino libraries are not implicitly exposed. This is targeted process confinement, not a complete sandbox for hostile native executables. Provider keys remain main-only, encrypted with Electron safeStorage when available. Main validates IPC, provider/model and payload limits. Imported files/model arguments/logs are data, not instructions. Tool calls use bounded targeted queries, validated transactions and revision checks. A proposal carries its base revision; application revalidates against the live state. No silent provider fallback.

Participation is local state. On request and Suggest do not infer from events. Suggest presents dismissible local pin/build actions. Proactive queues a failed human-started build only while a requested task is active, only at the current revision, and only with credentials/budget/cooldown/deduplication satisfied. It continues within that same task's limits; agent-initiated builds simply continue their explicit task in every mode. Typing, selection, movement, idle time and agent edits never start model work. Reported-token thresholds are checked after responses and can be crossed by that response; they are not a strict financial cap. Conversation/task summaries are persisted separately from project files. Profiles specify role/allowed tools separately from provider connections.

Build adapters target `arduino:avr:mega:cpu=atmega2560` and `esp32:esp32:esp32s3` with fixed default settings; ESP flash/PSRAM must be confirmed before physical operations. External [simavr](https://github.com/buserror/simavr) (GPL-3.0) provides bounded Mega execution. It is a separate local process, not linked into Electron; upstream calls >128 KB coverage preliminary. No USB/analog/power/current simulation is claimed. ESP32 simulation is unsupported. [Electron security](https://www.electronjs.org/docs/latest/tutorial/security), [React Flow handles](https://reactflow.dev/learn/customization/handles), [Dockview license/features](https://dockview.dev/docs/overview/licence/).

## Follow-up contracts (authoritative)

Project **version 2** adds explicit board settings, generic instance properties and telemetry mappings. `parseProject` migrates version 1 by adding these fields, retaining original part IDs/versions and endpoints. New reset examples explicitly use generic LED/resistor packages; old exact definitions are neither remapped nor assigned new values. Breadboard topology is immutable package data: independent five-hole groups and explicitly continuous BB830 rails. No component insertion is inferred from overlap.

`src/domain/semantics.ts` separates semantic freshness from monotonic transaction revisions. Build equality uses visible firmware, board package/version and compilation settings. Circuit equality adds target identity, properties excluding labels, connections and bindings; layouts, selection, panel arrangement and telemetry mappings do not invalidate it. Revisions still reject stale edit transactions. Exact retained artifacts use main-process SHA256 over configuration and generated file names/content, checked before upload; renderer cannot supply artifact paths or binaries. Verification and artifact preparation run fixed compiler processes against unchanged visible source. Export preserves source bytes and records target/configuration.

`src/services/hardware.ts` defines validated operations and snapshots. `desktop/hardware.ts` owns project synchronization, discovery, verification, immutable prepared requests, TTL, approval consumption, device identity, serialization and results. Every physical request initially waits; only separate main approval executes its stored parameters. No tool supports approve, arbitrary IPC, shell or filesystem access. Approval binds artifact/source/circuit/target/config/device, expires after two minutes and is one-use. Changed source/target/config/connectivity invalidates pending programming. Port changes cancel pending UI requests; disconnect/replacement rejects execution. Weak identity is disclosed; no silent alternate-port selection. Preparation/upload/observation cancellation uses known IDs. Interrupted programming clears known program identity; successful upload records it but cannot detect later external flashing.

Compiler/simulator confinement now denies physical device data access, including the former broad `/dev` allowance. Safe null/random/fd streams remain. Approved upload uses a separate generated profile granting only the selected validated serial device, fixed CLI arguments, no network, private scratch writes and bounded execution. SerialPort's N-API binding runs only in main under the approved hardware service, one owner per port. Native dependencies/prebuilds are packaged outside ASAR as needed; no privileged runtime enters the renderer.

`desktop/serial.ts` is a persistent event-driven service: UTF-8 chunk decoder, LF/CR/CRLF framing, maximum 8,192-character lines, 500 raw lines, 300 samples/channel and 32 configured channels. Raw malformed/truncated data remains visible, never a measurement. Main snapshots are throttled to 100 ms independently of ingestion; history truncation is counted. Explicit parser mappings use JSON dot paths or labeled `key=value` numeric records, finite numbers/booleans, optional explicit device timestamp, units and semantic meaning. No unlabeled-number guessing, implicit sensor polling or source injection. Parser state lives separately from firmware in project mappings. Disconnect stops condition waits; future observations subscribe immediately with cancellation and a maximum 30-second deadline. Read tools need no new approval for already-received data.

`request_hardware` creates and awaits an action-specific approval during a bounded requested AI task. It cannot approve itself or inherit approval from Proactive mode or code edits. Declined/expired identical actions are suppressed within the task. `inspect_hardware`, bounded `read_telemetry` and `observe_telemetry` never actuate hardware. Incoming samples and workspace switching do not trigger inference. Existing provider adapters/key isolation/participation budgets remain intact.

Native menus send a finite action vocabulary through preload. Separate Prototype/Debug Dockview layout keys share the same Zustand project and agent state. Preferences/approvals use native top-layer dialog focus containment. Hardware sessions, buffered readings and last upload metadata are session-local; parser mappings and project source/configuration are durable. No identity is claimed for an externally programmed device.

Serial open/close/write/drain/control-line callbacks have five-second deadlines, operation cancellation and generation checks. A cancelled or timed-out handle is abandoned with bounded best-effort close; a late successful open closes its old handle instead of reclaiming ownership. Byte transmission/reset cannot be undone. Approval records bind monitored baud/framing as well as device identity. Verify refuses to overlap an active hardware operation. Agent excerpts cap raw data at 8,000 characters and recent samples at 100 total; no continuous sample forwarding occurs.
