# Architecture

One Electron/React/TypeScript application. Main owns files, encrypted credentials, provider network access, fixed toolchain execution and cancellation. A sandboxed preload exposes a narrow validated IPC contract. Browser mode supports manual editing and explicitly lacks desktop services. Domain logic has no UI/runtime dependencies.

## Project format

`.trace.json` is UTF-8 JSON with `schemaVersion: 2`, project identity/name/revision, component instances, explicit wire endpoints, independent wiring/schematic placement maps, firmware files and pin bindings. Parts reference immutable built-in package ID/version. Each terminal has a stable ID independent of its label and rendering position. Package data records exact manufacturer/identity/revision, source URL/location/revision/fact/units/status, firmware and simulation capabilities. Unsupported package versions are rejected, never remapped silently.

Nets are derived connected components over endpoints plus explicitly modeled internal equivalences. A resistor/LED does not short its two pins. Layout is not circuit meaning. Selection, tool activity, viewport and output are transient or workspace preferences, never the circuit. Diagnostics carry source revision, affected object IDs, rule, severity, evidence and next action. Recompute local checks without inference. Execution results retain revision provenance; semantic input keys determine freshness separately.

## Commands

`transact(project, {expectedRevision, summary, commands})` validates all inputs and the resulting project before returning a new revision. Commands add/configure/remove parts, connect/disconnect, move/rotate in a named view, replace a firmware file, and set/remove explicit pin bindings. Removal cascades connections, layouts and bindings. One failed command rejects the entire group. Expected revisions reject stale agent mutations. Snapshot history supports grouped undo/redo, each advancing revision to prevent ABA conflicts.

Shared interaction store selects stable component/terminal/wire/diagnostic IDs. Panels subscribe; no panel imperatively changes another. Explicit navigation can reveal code/evidence without selection stealing focus. Dockview owns pane arrangement; React Flow owns gesture rendering, never canonical topology. Monaco uses local bundled workers/assets, no CDN.

## Modules

- `src/domain`: schema, commands, topology, rules, history, example and typed tool contracts.
- `src/parts`: sourced immutable part packages; original vector illustrations with separate terminals.
- `src/ui`: dock shell, circuit, code, agent, inspector, output and tokens.
- `src/services`: participation controller, provider/tool contracts and execution model.
- `desktop`: Electron lifecycle/preload, credentials, provider adapters and toolchain.
- `tests`: topology/transaction/persistence/rules, provider fixtures, participation and desktop workflow.

## Boundaries

No arbitrary filesystem paths or shell tool. File dialogs mediate project access; sketches compile in a private temporary directory. Compiler and simulator children inherit a macOS `sandbox-exec` profile: network I/O denied; regular file contents restricted to system/SDK/tool roots, selected Arduino package/index data and build scratch; writes restricted to scratch/safe standard streams. HOME is preserved, build config/cache/download/user directories are redirected explicitly to scratch, and provider environment variables are omitted. No unrestricted fallback. User Arduino libraries are not implicitly exposed. This is targeted process confinement, not a complete sandbox for hostile native executables. Provider keys remain main-only, encrypted with Electron safeStorage when available. Main validates IPC, provider/model and payload limits. Imported files/model arguments/logs are data, not instructions. Tool calls use bounded targeted queries, validated transactions and revision checks. A proposal carries its base revision; application revalidates against the live state. No silent provider fallback.

Participation is local state. On request and Suggest do not infer from events. Suggest presents dismissible local pin/build actions. Proactive queues a failed human-started build only while a requested task is active, only at the current revision, and only with credentials/budget/cooldown/deduplication satisfied. It continues within that same task's limits; agent-initiated builds simply continue their explicit task in every mode. Typing, selection, movement, idle time and agent edits never start model work. Reported-token thresholds are checked after responses and can be crossed by that response; they are not a strict financial cap. Conversation/task summaries are persisted separately from project files. Profiles specify role/allowed tools separately from provider connections.

Build adapters target `arduino:avr:mega:cpu=atmega2560` and `esp32:esp32:esp32s3` with fixed default settings; ESP flash/PSRAM must be confirmed before physical operations. External [simavr](https://github.com/buserror/simavr) (GPL-3.0) provides bounded Mega execution. It is a separate local process, not linked into Electron; upstream calls >128 KB coverage preliminary. No USB/analog/power/current simulation is claimed. ESP32 simulation is unsupported. [Electron security](https://www.electronjs.org/docs/latest/tutorial/security), [React Flow handles](https://reactflow.dev/learn/customization/handles), [Dockview license/features](https://dockview.dev/docs/overview/licence/).

## Follow-up contracts (authoritative)

Project **version 2** adds explicit board settings, generic instance properties and telemetry mappings. `parseProject` migrates version 1 by adding these fields, retaining original part IDs/versions and endpoints. New reset examples explicitly use generic LED/resistor packages; old exact definitions are neither remapped nor assigned new values. Breadboard topology is immutable package data: independent five-hole groups and explicitly continuous BB830 rails. No component insertion is inferred from overlap.

`src/domain/semantics.ts` separates semantic freshness from monotonic transaction revisions. Build equality uses visible firmware, board package/version and compilation settings. Circuit equality adds target identity, properties excluding labels, connections and bindings; layouts, selection, panel arrangement and telemetry mappings do not invalidate it. Revisions still reject stale edit transactions. Exact retained artifacts use main-process SHA256 over configuration and generated file names/content, checked before upload; renderer cannot supply artifact paths or binaries. Verification and artifact preparation run fixed compiler processes against unchanged visible source. Export preserves source bytes and records target/configuration.

`src/services/hardware.ts` defines validated operations and snapshots. `desktop/hardware.ts` owns project synchronization, discovery, verification, immutable prepared requests, TTL, approval consumption, device identity, serialization and results. Every physical request initially waits; only separate main approval executes its stored parameters. No tool supports approve, arbitrary IPC, shell or filesystem access. Approval binds artifact/source/circuit/target/config/device, expires after two minutes and is one-use. Changed source/target/config/connectivity invalidates pending programming. Port changes cancel pending UI requests; disconnect/replacement rejects execution. Weak identity is disclosed; no silent alternate-port selection. Preparation/upload/observation cancellation uses known IDs. Interrupted programming clears known program identity; successful upload records it but cannot detect later external flashing.

Compiler/simulator confinement now denies physical device data access, including the former broad `/dev` allowance. Safe null/random/fd streams remain. Approved upload uses a separate generated profile granting only the selected validated serial device, fixed CLI arguments, no network, private scratch writes and bounded execution. SerialPort's N-API binding runs only in main under the approved hardware service, one owner per port. Native dependencies/prebuilds are packaged outside ASAR as needed; no privileged runtime enters the renderer.

`desktop/serial.ts` is a persistent event-driven service: UTF-8 chunk decoder, LF/CR/CRLF framing, maximum 8,192-character lines, 500 raw lines, 300 samples/channel and 32 configured channels. Raw malformed/truncated data remains visible, never a measurement. Main snapshots are throttled to 100 ms independently of ingestion; history truncation is counted. Explicit parser mappings use JSON dot paths or labeled `key=value` numeric records, finite numbers/booleans, optional explicit device timestamp, units and semantic meaning. No unlabeled-number guessing, implicit sensor polling or source injection. Parser state lives separately from firmware in project mappings. Disconnect stops condition waits; future observations subscribe immediately with cancellation and a maximum 30-second deadline. Read tools need no new approval for already-received data.

`request_hardware` creates and awaits an action-specific approval during a bounded requested AI task. It cannot approve itself or inherit approval from Proactive mode or code edits. Declined/expired identical actions are suppressed within the task. `inspect_hardware`, bounded `read_telemetry` and `observe_telemetry` never actuate hardware. Incoming samples and workspace switching do not trigger inference. Existing provider adapters/key isolation/participation budgets remain intact.

Native menus send a finite action vocabulary through preload. Separate Prototype/Debug Dockview layout keys share the same Zustand project and agent state. Preferences/approvals use native top-layer dialog focus containment. Hardware sessions, buffered readings and last upload metadata are session-local; parser mappings and project source/configuration are durable. No identity is claimed for an externally programmed device.

Initial agent additions use `src/services/agentLayout.ts` to space overlapping artwork in both views before committing the validated transaction. Shared illustration dimensions live in `src/parts/illustration.ts`. Adjustments are explicit move commands in the same review/undo group and are reported in the tool result. Existing placements, electrical endpoints and source are preserved; this is visual spacing, not physical breadboard insertion or an electrical rule. Manual movement remains unrestricted and blocked wire routes remain visible.

Serial open/close/write/drain/control-line callbacks have five-second deadlines, operation cancellation and generation checks. A cancelled or timed-out handle is abandoned with bounded best-effort close; a late successful open closes its old handle instead of reclaiming ownership. Byte transmission/reset cannot be undone. Approval records bind monitored baud/framing as well as device identity. Verify refuses to overlap an active hardware operation. Agent excerpts cap raw data at 8,000 characters and recent samples at 100 total; no continuous sample forwarding occurs.

## In-app agent runtime (agent follow-up)

`src/services/instructions.ts` is the custom **in-app** system template (`trace-agent-14`). Repository AGENTS.md is for the implementing agent and is not injected into product requests. `src/services/agent.ts` assembles the template plus a compact goal/project/selected-diagnostic context; every task request passes it as `system`. `desktop/providers.ts` translates it to Gemini `systemInstruction`, Claude `system`, and OpenAI/xAI system messages. The connection test is a separate short connectivity request. Gemini is the implementation/live-evaluation focus; existing other adapters remain available and fixture-checked, without new live claims.

The template includes compact exact command shapes and explicitly directs actual creation/repair, preservation, source-backed pin queries, visible firmware/reporting, deterministic Debug mappings, checks/compilation, focused clarification for missing physical facts, and separate hardware approval. Tools (`trace-tools-13`) cover summary/targeted circuit queries, compact part facts/evidence, firmware regions, atomic edits including properties/bindings/telemetry, fresh diagnostic inspection, checks, Verify/build/MCU simulation, bounded output, deterministic `apply_diagnostic_fix`, explicit navigation and existing approval-gated hardware requests. `inspect_part` omits artwork/internal hole arrays; full terminal facts/evidence are targeted. Independent searches can use one bounded queries array; small-part results include stable terminals. Unknown-terminal errors return valid IDs. Zod failures return bounded path/message summaries instead of enormous union errors. Checks carry stable diagnostic IDs, source/rule evidence and freshness. Build/check results give compact freshness rather than sending semantic equality keys containing the entire firmware back to the model. Numeric-start terminal IDs such as Mega `5v`/`3v3` are valid, while component IDs retain the stricter identity grammar. Explicit Arduino A0–A15 pin constants are understood narrowly; arbitrary C++ remains unsupported.

Each task/segment records task UUID, provider request UUID, provider response ID where available, tool-call ID, message identity, timing, sizes, normalized usage and error metadata. No keys are logged. Bounded implementation reviews return local errors, resolvable hardware-interface warnings and stale/missing compilation before completion; a final goal/state summary keeps the whole request visible after compiler/binding repairs. Genuine physical facts remain distinct; the application status keeps those conditions distinct from a successful compile. Servo board-rail power, provisional encoder bus logic, literal telemetry delimiter mismatch, undeclared numeric units and component provenance have specific local rules. Missing LED current limiting has a deterministic fix only for an identified direct GPIO→anode/grounded-cathode path; it never assumes every LED/module topology needs an extra resistor. Generic resistor values can be increased under the configured nominal assumptions. Both fixes remain reviewable/undoable and never certify physical current. Tool results execute sequentially through the same transaction path. Gemini declares typed edit_circuit and update_firmware tools instead of the large discriminated command-union schema. Both translate to the same validated atomic project_changes coordinator; established adapters/internal fixtures retain that underlying contract. Failed calls return revision and bounded relevant connection conflicts. Search normalizes punctuation and includes exact package IDs; all catalog entries remain browsable. Gemini requests use documented `toolConfig.functionCallingConfig.mode=VALIDATED`; local schemas and semantic checks still validate every call. Duplicate Gemini function IDs/SSE IDs are coalesced; conflicting identity replay fails. For Gemini records lacking IDs, identical function name/arguments within one response are coalesced, while distinct records get request-scoped IDs. Distinct explicit IDs remain distinct. The coordinator memoizes completed calls and revision-scoped reads. Retries never execute incomplete response tools. At most two consecutive transport/502/503 retries use the same provider/model, count as requests and remain cancellable; 429 does not auto-retry or switch providers. Unknown usage on interrupted responses stays unknown. Repeated identical tool failures or unchanged cached inspection loops stop with useful status.

`src/services/agentSettings.ts` defines persisted per-task settings: 1,000,000 reported tokens, 32 model requests, 120 tools, 600 seconds, 8,192 response output tokens. These are independent maxima, not a context-window assertion, target, subscription allowance or spending cap. Previous releases hard-coded defaults and had no editable limit persistence. New `trace.agent-limits.v2` settings are explicit. Optional legacy v1 values equal to the old built-ins migrate; non-defaults or values marked explicit survive. A v2 explicit 24,000 setting stays 24,000. Existing preview policy is preserved; new profiles apply authorized reversible local edits. Preview keeps the task waiting on the specific proposal. Apply and continue commits once and continues automatically; Dismiss returns a declined result. Intervening edits invalidate the batch and return current-state feedback for replanning. No manual Resume is required between batches.

`src/services/usage.ts` normalizes cumulative response snapshots once per request ID. Gemini total includes prompt/candidates/thoughts; cached prompt is a subset. OpenAI/xAI reasoning/cache details are subsets of completion/prompt. Claude input adds base, cache creation and cache read; output streaming usage is cumulative. Missing/malformed counts stay null with warnings. Total is not added to its components. Repeated input on later successful requests is real reported usage. Gemini MALFORMED_FUNCTION_CALL retains usage but discards all partial tools; up to two consecutive bounded protocol repairs retry smaller typed calls without replaying completed mutations. A response may cross the threshold; **all further inference and pending tools then pause**. The application status records completed change groups, current compile state, cause and unexecuted calls without a final paid request. Switching to a different project cancels an active task before pending edits; a paused task is bound to its original project/provider/model. Explicit Continue task uses current limits/state, retains cumulative token/request/tool counters and active elapsed time (excluding the paused interval), revalidates pending revisions and retains completed-call identity. An unchanged exhausted limit remains exhausted; increase that setting to continue. Paused task context is in memory for this app session; restarting discards pending execution, never executes it automatically. Hardware approvals remain main-owned and never resumable/replayable as consumed approvals. Settings preserve a selected diagnostic through provider configuration; Explain is additionally enforced as read-only by dispatch, independent of prompt wording.

`npm run evaluate:gemini -- --cases led,servo-encoder --repeat 1` launches isolated Electron profiles, reads configured credentials only through the normal encrypted main boundary, and drives the actual renderer runtime/provider adapter/tool mutation path. User project files and hardware request/approval IPC are disabled in software evaluation. Parser/project data remain local to each case. Runtime hash, instruction/tool versions, requests/tools/usage/duration, artifact checks, bounded compiler output and failures go to ignored `artifacts/evaluations`. `--model`, `--requests`, `--tools`, `--tokens`, `--seconds`, `--batch`, a retained `--seed` snapshot for one selected case, optional `--gap-seconds` (0–60) and repeat 1–3 select bounded batches. Stop the batch on quota/credential failure. No automatic alternate-model selection. Fixture mode is isolated, uses clearly fake credentials/responses and the same runtime with the actual compiler. `src/evaluation/cases.ts` and `oracles.ts` cover 16 ladder cases with explicit nets, preservation, source/mapping/binding properties and semantic build freshness; no-diagnostics/model self-evaluation alone is never the oracle. See [evaluation results](evaluation.md).

## Continuous tasks and fresh sessions

The typed ask_user tool waits for one question with concrete options and optional free text in Agent. The response returns as tool data in the same task, never as a hardware approval. Question/review idle time is excluded from active task duration; no inference runs while waiting. Stop/cancellation rejects the pending interaction. Limits remain cumulative, independent and enforceable; only a genuine stopped task exposes Continue task.

Agent session UUIDs separate asynchronous work from project IDs. New Project/Open clears conversation, proposals/questions, task accounting, selection, output and history; resetting the indicator retains only its deliberate project undo behavior. New chat cancels its task and clears chat/context while retaining project work. Session persistence binds messages to project identity. Late provider/build results cannot repopulate a new project/chat.

Additional packages and their sources are in [catalog](catalog.md). Optional supply/capacitance/inductance properties persist in schema2. Adafruit757 channel transfer is signal reachability in domain/interfaces.ts, never electrical net equivalence. Rules check declared sources, required peripheral data/control/reference paths, translator references, and selected exact IC operating supply ranges; source requirements are not treated as voltage generators. Removing required wiring creates actionable errors and targeted repairs reject newly disconnected functionality. Generic hardware assumptions/physical current and mechanical behavior remain unknown. AS5600 chip protocol facts are separately versioned in parts/referenceFacts.ts; they do not reinterpret the module's immutable terminals.

Pinned Servo1.3.0 is an ordinary explicit firmware dependency. setup:libraries verifies its archive SHA256 and retains source/license under the fixed tool root; compile passes only that library root and installed cores under existing confinement. Packaging retains it and export records the dependency. No user library folders, new arbitrary roots or source injection were introduced. The supported-library-set identity participates in semantic build freshness.

The public `edit_circuit` tool supports coordinated additions, connections, removals, layout moves, properties, target/configuration, visible files, bindings and telemetry in one atomic batch. `update_firmware` uses the same coordinator for source-oriented work. Arrays upsert stable IDs; removals are explicit. The agent cannot assert a newly selected ESP variant is physically confirmed; the user confirms that configuration in Board settings. Public mutation trace entries record counts/paths rather than full source. Provider retry counters reset after a successful response; overall task budgets still bound the entire task.

Project → Servo and Encoder Example is an explicit manual template generated by `src/domain/servoExample.ts` through validated commands from `examples/servo-encoder/sketch.ino`. It is not an agent response shortcut or a live acceptance result. Its separate translated buses, external servo supply, visible reporting and persisted mappings exercise the ordinary model/compiler.

## Product naming compatibility

Visible product/application/menu/conversation identity is `mudroom`; packaged path is `release/mudroom-darwin-arm64/mudroom.app`. Legacy `.trace.json`, `window.trace`, event/storage keys and `dev.trace.workbench` remain compatibility identifiers. The established profile remains `Application Support/Trace`. Electron 44 binds macOS safeStorage identity during startup: keep startup name Trace until ready, then set visible app name mudroom. This preserves the keychain account/service instead of silently creating a new encryption key. See [Electron startup source](https://github.com/electron/electron/blob/v44.9.0/shell/browser/electron_browser_main_parts.cc). Test/evaluation profiles remain isolated. No credentials are migrated through the renderer.

Typography is local WOFF2 under `assets/fonts` using upstream JetBrains Mono v2.304, with OFL/source notices copied into package licenses. Monaco uses the shared CSS font/palette tokens and remeasures after loading. No font CDN or new dependency is required. Branding-only instruction version is trace-agent-14; tool contract remains trace-tools-13.
