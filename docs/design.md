# Design

Working identity: **Trace**. A quiet instrument for connecting hardware decisions to code. Graphite surfaces, warm off-white text, muted secondary labels and a mint accent. Copper/orange marks signal wires and warnings; red is reserved for errors. No decorative metrics or animated status noise.

Central tokens in `src/ui/tokens.css`: canvas, panel, raised surface, border, text, muted, accent, warning and danger; spacing, toolbar/row sizes, radius and monospaced font. System typography for chrome; bundled Monaco for firmware. Small consistent Lucide icons with tooltips and accessible labels. Keyboard focus is visible.

Default: wide circuit left, code center, agent right. Tabs and thin separators frame the content. Output collapses along the bottom; inspector overlays a compact contextual region of the circuit. Pane headers support maximize and floating; dragging tabs rearranges/stacks panels. Dockview uses pointer drag handling for consistent in-app gestures. Actual tab-group counts and splitter widths are verified in Electron, beyond element visibility. Layout reset is always available. Native icon uses the same original trace mark as the title bar.

Original vector board artwork conveys physical form without implying exact manufacturing dimensions. Terminal handles are 18 canvas pixels, with a 24-pixel connection snap radius; fit/zoom is available for dense Mega headers. Pins retain explicit identity; wire preview/snapping never connects crossings. Components drag independently from pin gestures. Selection persists across views and highlights linked code without changing active files. Evidence and code navigation require explicit actions.

Fit View reserves space for wire bends beyond component bounds; an Electron interaction check asserts that both components and visible paths fit. Wire routing currently uses React Flow's smooth orthogonal paths, without obstacle avoidance or manual bend editing. Connectivity always follows explicit endpoints, including when a path crosses another object.

Part library opens on demand. Selected objects reveal properties/evidence; blank canvas guides adding a part. Agent starts with one concise useful action and connection state, never fabricated prior conversation. Tool activity is compact and expandable. Grouped changes show named wiring/binding actions and a source diff; intervening edits disable stale proposals. Settings separate provider connections from participation policy. Capability labels distinguish verified mapping, constraints, compilation and execution models. Execution shows observed UART and digital transitions first, with the full build/simulator log on demand. Monaco's palette derives from centralized CSS tokens; legacy textarea input is selected explicitly for reliable desktop editing/automation.
