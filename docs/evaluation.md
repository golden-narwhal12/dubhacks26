Gemini-focused follow-up, 17 Oct 2026. Current instructions `trace-agent-13`, tools `trace-tools-13`; each batch records its frozen versions. Implementation uses the app runtime, not a second agent. Local reports are ignored under `artifacts/evaluations`; no credentials are in reports or projects.

## Findings

The original runtime used a hard-coded 24,000 reported-token threshold, six requests, twenty tools, ninety seconds and 2,048 output tokens. Input usage was accumulated across requests (legitimate repeated input); cumulative stream snapshots were overwritten, not summed. There is no evidence that the original observed threshold was caused by double accounting. It lacked IDs in chat activity, so the user's exact historical repetitions cannot be classified retrospectively.

A traced updated live run showed three genuinely distinct searches (Mega, LED, resistor), followed by three distinct part inspections with separate provider call IDs. The old UI presented every one as a full chat activity row. Additional concrete blockers were full part serialization, full firmware embedded in returned semantic equality keys, a preview loop that continued before applying proposals, numeric-start supply terminal IDs rejected by schema, and lack of Arduino analog-alias support in binding checks. These are fixed. Streaming/call replay, cumulative usage and budget resume now have deterministic regressions.

The latest implementation uses Gemini's documented VALIDATED constrained tool decoding while retaining local Zod/revision validation. The oracle failures were retained rather than relaxed to turn the model's claims into a pass.

Screenshot inspection of the final live LED artifact caught a separate visual failure: electrically valid parts were placed over the Mega artwork, blocking routes. A subsequent deterministic coordinator fix spaces only newly added artwork, preserving connectivity/source and existing placements. A same-runtime regression deliberately supplies overlapping positions and checks that routes are visible; focused tests cover spacing, rotation, unchanged nets/source and atomic revisions. The historical live artifact is retained rather than retroactively represented as visually correct.

## Reproduction

Build first: `npm run build`. Quick deterministic checks: `npm run check`. Runtime fixtures with real Mega compilation: `npm run evaluate:fixtures`. Full desktop checks: `npm run test:e2e`.

Paid live: `npm run evaluate:gemini -- --cases led,servo-encoder --repeat 1 --batch acceptance`. Then select `continue-circuit,continue-code,explain-led,repair-led,repair-binding,repair-compile,potentiometer,itr9608,combined` as access permits. `src/evaluation/cases.ts` lists all 16 IDs, including ambiguity and unavailable-capability cases. Repeat 1–3, explicit model/limits, `--gap-seconds 45` between cases, and a single-case retained `--seed` snapshot are supported. Explain/Fix evaluation uses the actual Issues → Ask Agent menu. Configure a key locally in Trace; never paste it in chat. A 429/credential failure stops further paid cases. No physical approvals are requested or executed by the software suite.

The primary oracle validates canonical endpoints/nets, actual packages, preserved work, explicit telemetry provenance/meaning, visible source constructs, diagnostic target resolution and current real build results. Equivalent valid pin choices are accepted. Clarification succeeds only for case-specific missing facts/unsupported capabilities. These scoped predicates do not prove arbitrary C++ behavior, peripheral ratings, external circuitry or mechanical operation. Fixture tests prove runtime contracts, not model versatility. There are positive live cases and retained failures; this small sample does not establish universal versatility or stable repeatability.

Official usage references: [Gemini usage metadata](https://ai.google.dev/api/generate-content), [OpenAI Chat usage](https://developers.openai.com/api/reference/resources/chat), [Claude cache accounting](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [xAI Chat usage](https://docs.x.ai/developers/advanced-api-usage/prompt-caching/usage-and-pricing). The first is the live implementation focus; other adapters were retained and fixture checked.
