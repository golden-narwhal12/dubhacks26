# Local execution

`desktop/toolchain.ts` compiles validated project firmware with the installed Arduino CLI. It supports Mega 2560 Rev3 (`arduino:avr:mega:cpu=atmega2560`) and Espressif ESP32-S3-DevKitC-1 v1.1 (`esp32:esp32:esp32s3`). ESP32 defaults are 4 MB flash, no PSRAM; the actual module variant still needs confirmation before a physical operation. No upload or serial-port access is performed.

The first `.ino` file (preferring `sketch.ino`) becomes `sketch/sketch.ino`; other files retain validated simple names. Duplicate names, including case-only duplicates, are rejected. Files and compiler outputs live in a private temporary directory, deleted after the result. Compiler arguments and supported board targets are fixed; no shell or model-provided build flags are accepted. A generated Arduino CLI configuration redirects user libraries, downloads and build cache to scratch, while reading installed board packages from the standard macOS Arduino15 directory. Existing user libraries/custom data directories are not implicitly supported. HOME is preserved. Output is limited to 64 KiB per process, compile time to 120 seconds, and simulation to a 3-second wall-time sample. Stop/cancel terminates the subprocess group, including compiler children, with forced termination after 500 ms if necessary. Returned results carry the compiled project revision.

On macOS both compiler and simulator run under a generated `sandbox-exec` profile inherited by child processes. It denies network I/O and regular-file contents outside explicit system/SDK/tool/package/index/scratch roots, and denies writes outside scratch/device streams. It allows filesystem metadata, inherited pipes and other required macOS runtime operations; broad system roots remain readable. This is targeted confinement rather than a complete hostile-native-code sandbox. Missing/unsupported confinement fails closed; no unrestricted build fallback. Tests use synthetic excluded files and a loopback connection attempt, never user secrets.

## Simulator setup

Run `node scripts/setup-simavr.mjs`. It requires Git, make, clang/Xcode command-line tools and network access for the initial source download. It builds pinned upstream simavr commit `5b08da60497f7564f50941f74a549fe2851db030` under ignored `artifacts/tools`, retaining the source, license and build metadata. No system installation is needed. The standalone executable is GPL-3.0-or-later; it is spawned externally, not linked into Electron. Packaging includes the prepared simulator with its license and corresponding source archive.

This build intentionally disables libelf/libdwarf and loads the compiler's Intel HEX output. The [official build files](https://github.com/buserror/simavr/blob/master/Makefile.common) permit a source-tree executable without system installation. The [upstream simulator](https://github.com/buserror/simavr) lists ATmega2560, UART and GPIO support, while describing support for AVR parts above 128 KB flash as preliminary. That limitation remains visible in the full simulation log. When available, `npm run package` includes the standalone helper, license, pinned source metadata and corresponding source archive in the local app bundle; it is not linked into Electron.

The simulation runs compiled ATmega2560 instructions at a configured 16 MHz. It captures actual emulated UART output and digital GPIO transitions for up to sixteen explicitly bound Mega signals, using documented package port/bit identities. Wall time and emulated time differ. It does not execute ESP32-S3 firmware or simulate the external LED, resistor, physical wiring, supply/current, or analog networks. A successful sample means the bounded MCU execution completed; it does not certify circuit correctness.

## Verification

`npx vitest run tests/toolchain.test.ts` verifies cancellation, subprocess timeout/output limits, literal argument passing, unsafe-path rejection and explicit ESP32 simulation unavailability. `TRACE_LIVE_TOOLCHAIN=1 npx vitest run tests/toolchain.test.ts` additionally compiles both requested board targets and executes the Mega example. These live checks require installed cores and simavr; they are opt-in rather than silently passing with mocks.

Observed on macOS arm64, 2026-10-17: Arduino CLI 1.5.1, AVR core 1.8.8, ESP32 core 3.3.11. All nine checks passed, including synthetic confinement checks. The Mega example compiled to 2,778 flash bytes and 238 SRAM bytes. The actual execution printed `Trace: indicator ready`, alternating `indicator ON` / `indicator OFF`, and recorded 73 digital transition samples on PB7 / documented D13 during one 3-second wall-time run. The transition count varies with host speed and is not a deterministic timing assertion. Both Mega and ESP32 builds succeeded. No physical board was involved.
